# 한마음 개발 채팅 인수인계

작성·확인 기준일: **2026-10-01 KST**  
대상: `hanmaum-frontend` / `hanmaum-backend` / `hanmaum-ai`의 새 개발 채팅

이 패키지는 긴 디자인 대화를 다시 설명하지 않고 개발을 시작하도록 만든 공통 기준이다. 제품 원문, 사용자 디자인 결정, 실제 코드 현황을 구분했다. **읽는 첫 문서는 COMMON.md이고, 구현 전에 담당 레포 지침을 읽는다.**

## 새 채팅에서 사용하는 방법

1. 담당 레포를 작업 위치로 지정해 채팅을 연다.
2. 아래 FE·BE·AI 시작 메시지 중 하나를 그대로 전달한다.
3. 채팅은 공통 기준 → 충돌/미정 → 담당 지침을 읽고, 맡은 기능의 원문·Figma·코드를 확인한 다음 작업한다.
4. 새 결정이나 구현 상태가 바뀌면 이 문서의 기준일과 관련 내용을 갱신한다. 과거 조회본을 최신 사실로 고정하지 않는다.

원본 링크만 주고 처음부터 추측하게 하는 대신, 여기서 결정 사항과 조회 지점을 함께 전달한다. 이 패키지만 읽었다고 최신 원문·전체 코드를 확인한 것으로 간주하지는 않는다.

## 먼저 알아둘 세 가지

- **기능 DB 100개를 개별 페이지까지 읽었다.** Must 67 / Should 15 / Could 9 / Won't 9. 개별 페이지의 상세 본문은 모두 비어 있고, 실제 설명은 DB 속성에 있다. 없는 상세 정책을 만들어 채우지 않았다.
- **화면과 기반 코드는 있으나 실제 서비스 구현은 시작 단계다.** FE는 초기 데모, BE는 세션·CSRF·OAuth·AI 통신 기반, AI는 빈 제안 배열을 반환하는 stub이다. Figma의 356개 예시는 라우트 수나 개발 완료량이 아니다.
- **BE 초기 권한 표가 제품 정책과 다르다.** 구성원의 일반 변경은 요청이고 소유자가 최종 반영한다. 본인 담당 할 일 상태와 본인 소식 삭제 등 명시된 예외를 구분한다.

## FE 새 채팅 시작 메시지

아래를 복사해서 FE 채팅에 전달한다.

```text
한마음 FE 개발을 시작하자. 작업 레포는 C:/dev/Hanmaum/hanmaum-frontend다.

먼저 C:/dev/Hanmaum/docs/handoff/README.md, COMMON.md, DECISIONS.md, FE.md, TOKENS.md, FIGMA.md를 읽어줘. 관련 기능은 FEATURES.md와 sources/notion-policy.md에서 확인하고, 해당 Figma 상세 UI를 직접 조회해줘.

현재 Git 상태와 실제 코드를 확인한 뒤 기존 React/Vite/Tailwind/pnpm 설정을 유지하면서 공통 토큰·Noto Sans KR 타이포그래피·로고/아이콘 기반부터 구현해줘. 이어서 일반 버튼, Google/카카오 전용 로그인 버튼, 입력, 헤더 등 첫 흐름에 필요한 컴포넌트를 상태별로 확인할 수 있게 만들어줘. 로그인 대표 화면으로 조합을 검증한 후 화면을 확장하자. 첫 작업에서 모든 화면을 한 번에 구현할 필요는 없어.

제품은 휴대폰 중심 웹앱이고 하단 탭은 홈/돌봄/소식/가족/전체다. 최신 상세 UI를 기준으로 하고 초기 와이어프레임이나 데모를 최종 UI로 사용하지 마. 프로토타입 연결은 필요 없어.

BE는 세션 쿠키와 CSRF 기반이며 공개 도메인 API는 아직 미완성이야. API가 없으면 Mock임을 명확히 하고, 구성원 요청과 소유자 최종 반영을 구분해줘. 기존 구현을 다시 초기화하지 말고, 문서에 없는 정책은 확정하지 말아줘. 필요한 질문은 묶어서 하되 영향 없는 구현은 계속 진행해줘.

완료 후 변경 파일, 확인한 Figma/기능 ID, 실행한 검증, 남은 BE 연동 의존성을 알려줘. 다른 레포 변경·새 채팅 생성·메시지 전송·배포는 이번 시작 요청에 포함하지 않아.
```

## BE 새 채팅 시작 메시지

```text
한마음 BE 설계를 시작하자. 작업 레포는 C:/dev/Hanmaum/hanmaum-backend다.

먼저 C:/dev/Hanmaum/docs/handoff/README.md, COMMON.md, DECISIONS.md, BE.md, FEATURES.md와 sources/notion-policy.md를 읽어줘. 화면과 흐름은 FIGMA.md에서 해당 노드를 확인해줘.

기존 코드와 Git 상태를 확인하고, docs/architecture.md의 구성원 권한 설명을 최신 제품 정책과 맞춰줘. 세션·CSRF·OAuth·공통 오류·BE↔AI 계약은 이미 있으니 다시 초기화하지 마.

첫 단계는 Must 중심 논리 ERD, 권한/상태 전이와 삭제 전파 설계, 핵심 API 명세, 공통 응답·오류 규격을 구체적으로 검토할 수 있게 만드는 거야. ERD Cloud에 옮길 수 있는 구조로 정리하고 실제 대상 파일 접근이 필요하면 알려줘. 아직 없는 ERD Cloud 파일이나 도메인 API가 완성되었다고 가정하지 마. 검토할 설계가 나온 뒤 도메인 구현을 이어가자.

소유자 최종 반영, 구성원 예외 권한, 선택 제안 묶음의 원자적 반영, 반복 요청, 잠금/버전, 원본 삭제의 파생 내용 제거를 ERD와 API에 반영해줘. Figma 화면 수만큼 API를 만들거나 문서에 없는 필드 정책·TTL을 임의 확정하지 마.

FE와 AI가 필요한 입출력·오류·의존성을 따로 정리하고, 확정 정책과 제안/미정을 구분해줘. 질문이 필요한 부분을 모으되 영향 없는 설계는 진행해줘. 다른 레포 변경·새 채팅 생성·메시지 전송·배포는 이번 시작 요청에 포함하지 않아.
```

## AI 새 채팅 시작 메시지

```text
한마음 AI 개발 준비를 시작하자. 작업 레포는 C:/dev/Hanmaum/hanmaum-ai다.

먼저 C:/dev/Hanmaum/docs/handoff/README.md, COMMON.md, DECISIONS.md, AI.md를 읽어줘. FEATURES.md의 AI/Proposal/Record 항목과 sources/notion-policy.md의 관련 정책, AI·BE 양쪽 docs/ai-contract.md와 실제 DTO를 대조해줘.

현재 Git 상태와 FastAPI 코드부터 확인해줘. 현재는 stub이며 실제 자연어 분석·LLM 모델은 구현되지 않았어. 기존 인증·검증·오류·테스트 기반은 유지해줘.

첫 산출물은 Must 분석 요구사항과 현재 계약의 차이, 중복 근거 연결/상충 표시 등 BE와 합의할 계약 초안, 합성 평가 데이터와 평가 기준, 제공자/모델 연동 계획으로 만들어줘. 모델·비용·재시도 정책을 임의 확정하지 말고, 실제 모델 선정 후 기존 provider 구조로 연결하자.

AI는 제안만 반환하고 DB 변경·권한 판정·자동 반영은 하지 않아. 상대 날짜는 원본 recordedAt와 Asia/Seoul 기준으로 고정하고, 모호한 대상은 후보로 남기며 없는 사실·시간·담당자를 만들어 넣지 마. 분석 상태와 원본 삭제 중 늦은 결과 처리, 요청 중복은 BE와 계약을 맞춰야 해.

평가용 합성 데이터와 실제 서비스 데이터를 구분하고, 계약 테스트와 실제 모델 품질을 따로 보고해줘. 다른 레포 변경·새 채팅 생성·메시지 전송·배포는 이번 시작 요청에 포함하지 않아.
```

## 공통 자료의 보관과 갱신

이 폴더는 **C:/dev/Hanmaum/docs/handoff**에 있다. 현재 C:/dev/Hanmaum은 Git 저장소가 아니며 이 패키지는 세 레포 어느 쪽에도 커밋되어 있지 않다. 같은 로컬 Hanmaum 작업 공간의 새 채팅은 이 절대 경로를 읽을 수 있다. 다른 컴퓨터·원격 작업 공간·팀원에게는 이 폴더를 별도로 전달하거나 공통 문서 저장 위치를 정해야 한다.

공통 정책을 세 레포에 각각 복사해 서로 다르게 고치는 방식보다, 공통 원본을 한 곳에 두고 각 레포에서 참조하는 방식을 권장한다. Git에 보관할 위치와 운영 방식은 아직 정하지 않았다.

이번 작업은 이 인수인계 패키지만 작성했다. Notion·Figma·세 레포의 소스 코드는 수정하지 않았고, 새 채팅 생성·메시지 전송·커밋·PR·배포도 수행하지 않았다.
