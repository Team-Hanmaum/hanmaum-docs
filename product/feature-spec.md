| 분류 | 내용 |
| --- | --- |

| Dashboard (현황판) | 예정·지난 일정, 남은 할 일, 미확인 확인사항, 최근 확정 변경 조회 |

| Share (카카오톡 공유) | 최소 정보 카드 공유, 로그인·공간 참여 확인 후 상세·답변, 비구성원 참여 안내 |
| Notification (알림) | 서비스 내부 알림, 본인 담당 할 일 기본 수신, 개인 설정·읽음·중복 방지 |
| Common (공통·접근 환경) | 모바일 홈 화면 설치와 서비스 진입 지원 (Could) |

### MoSCoW (모스크바, 기능 우선순위)

- **Must Have** 프로젝트의 본질적 목표 달성과 정상 구동을 위해 무조건 구현해야 하는 핵심 필수 기능
- **Should Have** 핵심 동작에는 지장이 없지만, 서비스의 완성도와 사용성을 위해 가급적 구현해야 하는 권장 기능
- **Could Have** 시간과 개발 리소스에 여유가 있을 때 추가하면 좋은 부가적인(Nice-to-have) 기능
- **Won’t Have** 이번 MVP에서 구현 범위에 포함하지 않는 기능

| REC-08 | Could | 소식 상세 검색·필터 | 기간·작성자·영역 등의 조건으로 소식 원본을 검색·필터링, 관리 항목 검색과 분리하고 삭제된 원문은 검색 결과에서 제외 |

### AI (분석·기존 정보 연결)

| 기능 ID | MoSCoW | 기능명 | 기능 설명 |
| --- | --- | --- | --- |
| AI-01 | Must | 소식의 관리 항목 분류 | 하나의 소식에서 일정·할 일·확인사항·관찰·안내에 해당하는 내용을 나누어 항목 유형 결정, 날짜·내용 등 세부 값 추출은 AI-02로 구분 |
| AI-02 | Must | 관리 항목 정보 추출 | 분류된 항목의 날짜·시간·내용·질문 등 세부 값 추출, 상대 날짜는 소식 등록 시점과 Asia/Seoul 기준으로 해석하고 재분석 시에도 같은 기준 유지. 과거 발언 인용 등 기준이 불분명하거나 언급되지 않은 값은 임의 확정하지 않고 확인 요청 |
| AI-03 | Must | 기존 관리 항목 연결 | 같은 공간의 유효한 기존 항목에서 새 소식과 관련된 대상을 찾아 연결 후보 생성, 삭제된 원문·파생 내용은 재분석 근거에서 제외하고 소유자 확인 전에는 연결 확정 금지 |
| AI-04 | Must | 추가·변경·해소 제안 생성 | 신규 항목 추가·기존 항목 변경·확인사항 해소를 구분해 제안, 일정 취소·상태 변경도 변경 제안에 포함하고 소유자 승인 전에는 현재 정보 유지 |
| AI-05 | Must | 불분명한 연결 후보 제시 | 기존 항목과의 연결이 불분명하면 후보와 불확실한 내용을 제시, 구성원은 후보를 검토해 연결 요청을 제출하고 소유자가 최종 연결 대상 확정 |
| AI-06 | Must | 제안 근거 연결 | 각 제안을 입력 원문의 근거 문장 및 관련 기존 항목과 연결해 판단 근거 제공, 원본 삭제 시 인용문·복사된 내용을 REC-11에 따라 함께 제거 |
| AI-07 | Must | AI 분석 결과 검증 | 항목 유형·필수 정보·근거 연결의 유효성 확인, 사용자에게서 나오지 않은 사실을 확정 정보로 제시하지 않도록 검증 |
| AI-08 | Must | AI 분석 상태·실패 재시도 | 분석 진행·완료·실패 상태 안내와 실패 재시도 제공, 재시도 시 동일한 상대 날짜 기준 유지 및 중복 제안 생성 방지. 원본 삭제 시 해당 분석 중단 또는 결과 폐기로 삭제 내용의 재생성 방지, 재시도만으로 현재 정보 변경 금지 |

| AI-18 | Must | 상충 소식 탐지·확인 요청 | 날짜·내용 등이 서로 다른 소식은 양쪽 근거와 함께 확인 필요 대상으로 표시, 최신 소식만으로 기존 값을 덮어쓰지 않고 현재 값을 유지하며 소유자 비교·승인 후 확정 |

| AI-10 | Should | 새 참여자용 돌봄 브리핑 | 현재 유효한 일정·남은 할 일·미확인 사항·최근 변경을 바탕으로 새 가족에게 필요한 내용 요약, 삭제되었거나 근거 재확인 전인 항목은 확정 정보에서 제외 |
| AI-11 | Should | 추가 확인 질문 제안 | 추가로 확인하면 좋은 질문을 사용자 발언에서 추출한 확인사항과 구분해 제안, 소유자가 선택·승인한 경우에만 등록하고 구성원의 선택은 등록 요청으로 처리 |
| AI-12 | Won't | 건강 상태 판단·진단 | 기록을 바탕으로 건강 상태를 판단하거나 질환을 진단하는 기능은 이번 MVP에서 제외 |

<a name="proposal"></a>

### Proposal (제안 확인·반영)

| 기능 ID | MoSCoW | 기능명 | 기능 설명 |
| --- | --- | --- | --- |
| PROP-01 | Must | 제안 목록·처리 상태 조회 | 소식별 AI 제안과 검토 대기·승인 요청·반영·미적용 상태 조회, 구성원의 요청과 소유자가 반영한 결과를 구분하고 필요한 검토 화면으로 연결 |
| PROP-02 | Must | 제안 상세·변경 전후 비교 | 제안 유형·대상 항목·반영할 내용·원본 근거를 함께 확인하고 기존 정보와 제안 내용의 차이 비교 |
| PROP-03 | Must | 기존 정보 연결 대상 선택 | 불분명한 연결 후보에서 실제 대상을 검토·선택, 구성원의 선택은 승인 요청으로 제출하고 소유자만 최종 연결 확정. 적절한 대상이 없으면 보류하고 자동 연결 금지 |
| PROP-04 | Must | 제안 내용 수정 | 반영 전 제안의 내용·날짜·담당자 등 사용자 입력 가능한 값을 항목 유형에 맞게 수정, 원본 기록과 분석 근거는 임의 변조하지 않고 구성원의 수정안은 소유자 승인 요청으로 제출 |
| PROP-05 | Must | 제안 확인·적용 | 소유자가 제안을 개별 선택해 수정·확인한 뒤 선택한 제안만 추가·변경·해소로 반영, 기존 정보 연결·중복·상충 처리에도 소유자 승인 적용. 구성원은 반영 요청만 가능하며 최종 반영자·시점·근거를 이력에 보존 |
| PROP-06 | Must | 제안 미적용 처리 | 선택하지 않은 제안은 검토 대기로 유지하고 소유자가 명시적으로 받아들이지 않은 제안만 미적용 처리, 미적용·보류만으로 현재 정보 변경 금지 |
| PROP-07 | Must | 선택 제안 일괄 검증·중복 반영 방지 | 선택한 제안 전체의 권한·대상 버전·편집 잠금·필수 값을 적용 직전에 검증, 하나라도 충돌하면 모두 미반영하고 재확인 안내. 문제 제안을 선택 해제한 뒤 나머지만 다시 적용 가능하며 반복 요청에 따른 중복 반영 방지 |
| PROP-10 | Must | 변경 요청 제출·소유자 검토 | 구성원이 AI 연결·반영, 직접 등록·수정·삭제, 확인사항 답변 및 공간 정보 수정 요청을 제출하고 처리 상태 확인. 소유자가 요청 내용·근거·최신 상태를 검토해 승인·미적용 결정, 승인 전에는 현재 정보 유지. 본인 담당 할 일의 상태 변경과 허용된 원본 삭제는 별도 권한 적용 |
| PROP-08 | Should | 추가 확인 질문 선택 등록 | 추가 확인 질문을 개별 선택해 소유자 승인 후 미확인 확인사항으로 등록, 구성원의 선택은 등록 요청으로 처리하고 선택하지 않은 질문은 자동 등록 금지 |
| PROP-09 | Won't | AI 자율 정보 확정 | 소유자 승인 없이 AI가 현재 정보를 추가·변경·해소하거나 연결·제안을 자동 확정하는 기능은 이번 MVP에서 제외 |

| ITEM-08 | Must | 확인사항 답변·해소 | 가족이 답과 근거를 제출하면 기존 확인사항에 연결된 승인 요청으로 보존, 소유자가 확인·반영할 때 확인됨으로 전환. 답변 제출·단순 열람과 최종 해소를 구분 |

| SHARE-05 | Must | 공유 링크의 현재 정보 조회 | 공유 링크를 열 때 최신 확정 정보 조회, 삭제·접근 권한 상실 시 상세 대신 접근 불가 안내. 근거 재확인 중인 정보는 그 상태를 표시하고 삭제된 원문·파생 내용 재노출 금지 |
